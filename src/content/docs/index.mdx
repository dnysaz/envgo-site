## Why envGo

`fetch()` calls written in front-end JavaScript ship your API key to every
visitor. A conventional backend fixes that but brings a runtime, a dependency
tree, and a deployment to maintain.

envGo is the narrow alternative: a single static binary that serves your HTML and
holds the key. No Node.js, no `node_modules`, no runtime to install — roughly
2–8 MB depending on platform.

## Core features

    restart.
  </Card>

  </Card>
  <Card title="Built-in diagnostics" icon="magnifier">

## Quick start

### 1. Install

<Tabs>
  <TabItem label="Windows">

[⬇ envgo-windows-amd64.exe](https://github.com/dnysaz/envgo/releases/latest/download/envgo-windows-amd64.exe)
· [ARM64 build](https://github.com/dnysaz/envgo/releases/latest/download/envgo-windows-arm64.exe)

```powershell
mkdir C:\envgo
copy $env:USERPROFILE\Downloads\envgo-windows-amd64.exe C:\envgo\envgo.exe
[Environment]::SetEnvironmentVariable(
  "Path",
  [Environment]::GetEnvironmentVariable("Path", "User") + ";C:\envgo",
  "User"
)
# Open a NEW terminal, then:
envgo -v
```

  </TabItem>
  <TabItem label="macOS">

[⬇ Apple Silicon](https://github.com/dnysaz/envgo/releases/latest/download/envGo-macOS-AppleSilicon.zip)

```bash
mkdir -p ~/.local/bin

chmod +x ~/.local/bin/envgo
envgo -v
```

  </TabItem>


### 2. Create a project and run it

The next two commands are identical on every platform:

```bash
mkdir myapp && cd myapp
envgo init      # writes .env, .env.example, index.html, .gitignore, README.md
# put a real key in .env, then:
envgo run dev   # opens http://127.0.0.1:8080/
```

Your page uses the key without ever seeing it:

```html
<div id="MY_SECRET"></div>
<script src="/__env.js"></script>
```

```javascript
// The browser sends the literal text {OPENAI_API_KEY};
// the Go process substitutes the real value before forwarding.
await fetch("/proxy", {
  method: "POST",
  headers: { "Content-Type": "application/json", "X-EnvGo-Token": token },
  body: JSON.stringify({
    target_url: "https://api.openai.com/v1/chat/completions",
    headers: { Authorization: "Bearer {OPENAI_API_KEY}" },
  }),
});
```

The page above pairs with this `.env` — the `<div id="…">` elements and every
`{…}` placeholder must match a key in the file:

```env title=".env"
MY_SECRET=some-real-value
OPENAI_API_KEY=sk-your-real-key-here
HOST=127.0.0.1
PORT=8080
```

`HOST` and `PORT` are not secrets — they choose where `envgo run dev` listens, so
changing `PORT=8080` to `PORT=3000` makes it serve `http://127.0.0.1:3000/`
instead. They only apply to `envgo run` and `envgo run dev`; a flag like
`--port 4000` overrides them.

## Choose a mode

| | Local mode | Public mode |
|---|-----------|-------------|
| Enable with | *(default)* | `--config envgo.routes.json` |
| Browser calls | `/proxy` with a session token | `/api/<name>`, no token |
| Target URL comes from | The browser, restricted by `--allow` | The config file |
| Rate limiting | None | Per-route, per-IP |
| Use for | Development and private tools | Anything publicly reachable |

## Free, and open source

envGo is **MIT licensed**. Free for personal and commercial use, with no paid
tier, no licence key, no usage limit, and no telemetry — the binary makes no
outbound connections of its own, only the upstream calls you ask it to proxy.

Feedback is genuinely welcome, and a confusing error message is as useful to hear
about as a bug. See [License & feedback](/license) for where to report an issue,
ask a question, or propose a change.

## Known limitations

envGo is deliberately small, and it is worth knowing what that costs:

- **Streaming responses are not redacted.** SSE passthrough skips scrubbing, so an
  upstream that echoes a key inside a stream will leak it to the browser.
- **`default_rate_limit` is empty by default**, which means *unlimited*. Rate
  limiting must be opted into explicitly.
- **If PHP is unavailable or fails, the `.php` source is served as a file** rather
  than producing an error.
- **Rate limiting is per process.** Multiple instances each enforce their own
  limit, and behind a proxy without `trust_proxy: true` all clients share one
  bucket.
- **The session token is not user authentication.** It is per process, has no
  expiry, and any page on your own origin can fetch it.

The full list is in the [Threat Model](/reference/threat-model).
