This page documents the full `envgo` command-line interface. Every flag, its short
form, its default value, and its exact behaviour is listed below.

## Command syntax

```bash
envgo [subcommand] [flags] [arguments]
```

:::tip[Running bare `envgo` prints help]
Typing `envgo` with **no arguments at all** prints the help text and exits. It
never starts a server. This is deliberate — silently listening on `127.0.0.1:8080`
looks like a hang and gives no clue what to type next.

To start a server, name what you want: `envgo run dev`, or pass at least one flag
such as `envgo -e .env -p 3000`.
:::

:::caution[Subcommand must come first]
The subcommand (`run`, `init`, `deploy`) must be the **first** argument.

- `envgo run dev --debug` ✅ works
- `envgo --debug run dev` ❌ does **not** start dev mode

envGo only inspects `os.Args[1]` to detect a subcommand. In the second form the
`--debug` flag is parsed, but `run dev` is treated as ignored positional
arguments — so you get a plain server with debug logging, **not** dev mode.
:::

## Starting the server

envGo has two modes, selected by `--config` **or** `.env`:

| Invocation | Mode | What it does |
|------------|------|--------------|
| `envgo` | — | Prints help and exits. No server is started |
| `envgo run` | Local | Static file server + `/proxy` with session token, reads `HOST`/`PORT` from `.env` |
| `envgo run dev` / `envgo dev` | Local (dev) | Same as `run`, and always opens a browser |
| `envgo -e .env` | Local | Server with flags only — `.env` supplies variables, but not `HOST`/`PORT` |
| `envgo --config routes.json` | Public | Fixed routes at `/api/<name>`, no token handshake |
| `MODE_PUBLIC=true envgo run` | Public | Same as `--config`, but via `.env` (`CONFIG` optional) |

## Commands

| Command | Description |
|---------|-------------|
| `envgo` | Print help and exit — a bare `envgo` never starts a server |
| `envgo run` | Start the server and read `HOST`/`PORT` from `.env` |
| `envgo run dev` | Start in dev mode (implies `--browser`) |
| `envgo dev` | Alias for `envgo run dev` |
| `envgo run update` | Check for and install the latest envGo release in place |
| `envgo cache clear` | Broadcast a hard reload to all connected dev-server browser tabs |
| `envgo init` | Create a starter project in the current directory |
| `envgo init -name myapp` | Create the starter project in a new `myapp/` directory |
| `envgo deploy` | Generate `Caddyfile`, `nginx.conf`, `Dockerfile` |
| `envgo -v` | Print version and exit |
| `envgo -h` | Show help and exit |

:::caution[`envgo cache` needs its subcommand]
`envgo cache` on its own prints `Usage: envgo cache clear` and exits. The
subcommand `clear` is not optional.
:::

## Flags

| Flag | Short | Type | Default | Description |
|------|-------|------|---------|-------------|
| `--port` | `-p` | int | `8080` | Port to listen on |
| `--host` | | string | `127.0.0.1` | Interface to bind. Keep `127.0.0.1` for local-only access |
| `--dir` | `-d` | string | `.` | Web root directory to serve |
| `--env` | `-e` | string | `.env` | Path to the `.env` file |
| `--allow` | `-a` | string | *(empty)* | Comma-separated outbound host allowlist |
| `--config` | `-c` | string | *(empty)* | Path to routes JSON. Setting it enables **public mode** |
| `--dashboard` | `-D` | bool | `false` | Enable the metadata dashboard in public mode |
| `--tls` | | bool | `false` | Serve HTTPS with an auto-generated self-signed certificate |
| `--browser` | `-b` | bool | `false` | Open the browser automatically after start |
| `--qr` | | bool | `false` | Bind all interfaces and print a scannable QR code of the LAN URL |
| `--qr-format` | | string | `ansi` | QR output: `ansi` (terminal) or `png` (file) |
| `--debug` | | bool | `false` | Verbose logging |
| `--name` | | string | *(empty)* | Project name for `envgo init` (empty = current directory) |
| `-o` | | string | *(empty)* | Output directory for `envgo deploy` (default: `./deploy`) |
| `--version` | `-v` | bool | `false` | Print version and exit |
| `--help` | `-h` | bool | `false` | Show help and exit |

## Behaviour details

### Port fallback

If the requested port is already in use, envGo tries the next 19 ports
(`8080` → `8081` → … → `8099`) before giving up. The address actually bound is
printed at startup, so check the log if you do not get the port you asked for.

### Sharing with a phone: `--qr`

`--qr` answers "how do I open this on my phone?" — it binds every interface so
other devices on the same Wi-Fi can reach the server, then prints a QR code that
encodes the **LAN** address.

```bash
envgo run dev --qr
```

Key details:

- **Both URLs are printed.** `local` is for this machine, `network` is the one to
  scan. The QR always encodes the LAN address — never `127.0.0.1`, which is
  meaningless from a phone.
- **Only the host changes.** The port is whatever `.env` or `--port` resolved to.
- **`--qr` works with or without `run dev`.** `envgo -e .env --qr` is fine; the
  subcommand is not required.
- **You do not need to pass `--host`.** `--qr` overrides a `127.0.0.1` default. If
  you *did* set `--host` to a specific non-loopback address, envGo leaves it
  alone.

:::caution[`--qr` makes the server reachable on your network]
Without `--qr` the server binds `127.0.0.1` and no other device can reach it.
With `--qr` it binds `0.0.0.0`, so anyone on the same network can load your site
and reach the `/proxy` endpoint (subject to the session token, `Origin`, and
`Host` checks). Stop the server when you are done.

If the phone cannot connect, the port is usually blocked by the host firewall —
see [Sharing with your phone](/guides/sharing-with-your-phone).
:::

#### `--qr-format`

| Value | Result |
|-------|--------|
| `ansi` *(default)* | Prints the QR to the terminal using block characters |
| `png` | Writes `qrcode_<ip>_<port>.png` in the current directory |

```bash
envgo run dev --qr --qr-format png
# [envGo] QR code for http://192.168.1.20:8080 written to qrcode_192.168.1.20_8080.png
```

Use `png` when your terminal mangles the block characters — SSH sessions, some
Windows consoles, and CI logs commonly do. Only the literal value `png` (any
case) switches to file output; anything else falls back to the terminal, so a
typo like `--qr-format image` prints to the terminal instead of erroring.

The QR is rendered by an encoder built into the binary (no dependency, no
network call), so it works fully offline.

### `HOST`, `PORT`, and `MODE_PUBLIC` from `.env`

`HOST`/`PORT` are only read when you use `envgo run` or `envgo run dev`, **and** only if
you did not override them on the command line:

- `HOST` is used only when `--host` is still at its default `127.0.0.1`
- `PORT` is used only when `--port` is still at its default `8080`

Both uppercase (`HOST`) and lowercase (`host`) keys are accepted. A leading colon
in `PORT` is stripped, so `PORT=:3000` works.

`MODE_PUBLIC` / `CONFIG` are read **on every start**, when `--config` is not given:

- `MODE_PUBLIC=true` / `1` / `yes` / `public` → public mode (looks for `envgo.routes.json` or `routes.json`)
- `MODE_PUBLIC=false` / `0` / `no` / `local` → local mode
- Aliases: `MODE`, `PUBLIC_MODE`, `ENVGO_MODE` (same values)
- `CONFIG` / `ENVGO_CONFIG` / `ROUTES` = explicit path (wins over `MODE_PUBLIC`), relative paths resolved against `.env` dir and `--dir`
- Flag `--config` always wins over `.env`

Example:

```dotenv
# .env
MODE_PUBLIC=true
# or CONFIG=custom/myroutes.json
```

```bash
envgo run dev   # no flag needed — reads MODE_PUBLIC from .env
```

With plain `envgo --config … --port 8080`, `.env` is **not** consulted for
`HOST`/`PORT`. This trips people up when editing `.env` to change the port of a
systemd service — pass `--port` explicitly there instead.

### Security default: no `--allow` means no proxy

If `--allow` is empty **and** you are not in public mode, envGo prints a warning
and disables the proxy entirely:

```text
[envGo] WARN no --allow set: proxy is DISABLED for security. Use -a/--allow host1,host2
```

This is deliberate SSRF protection. Host matching accepts exact hosts and
subdomains, so `--allow openai.com` also permits `api.openai.com`.

### `.env` vs `.env.example` check

At startup envGo compares key names in the file given by `--env` against
`.env.example` in the same directory and prints a warning per mismatch:

- a key in `.env` but not in `.env.example` → `warning`
- a key in `.env.example` but not in `.env` → `hint`

Values are never compared.

### Public mode disables the local endpoints

When `--config` is set **or** `MODE_PUBLIC=true` / `CONFIG` in `.env` enables public mode, `/proxy`, `/__envgo_token`, the legacy `/__env/*` path
and the dashboard are all disabled (the last one unless you also pass
`--dashboard`). Only `/api/<name>` plus static files are served.

### Shutdown

`SIGINT` (Ctrl-C) and `SIGTERM` trigger a graceful shutdown with a 3-second
drain timeout, so in-flight responses get a chance to finish. This is what
`systemctl stop envgo` sends.

## Examples

All examples below use placeholder values — replace them with your own.

```bash
# Start a local server with an explicit directory, env file, and allowlist
envgo --dir . --env .env --allow httpbin.org

# Dev mode: reads HOST/PORT from .env and opens the browser
envgo run dev

# Open it on your phone: bind the LAN interface and print a scannable QR code
envgo run dev --qr

# Same, but write the QR to a PNG file instead of the terminal
envgo run dev --qr --qr-format png

# Dev mode with verbose logging (flag AFTER the subcommand)
envgo run dev --debug

# Different port, restricted allowlist, auto-open browser
envgo -p 3000 -d . -e .env -a api.openai.com -b

# Public mode: fixed routes, no token handshake (via flag)
envgo --config envgo.routes.json --env .env --dir . --host 127.0.0.1 --port 8080

# Public mode via .env (no flag) — set MODE_PUBLIC=true or CONFIG=envgo.routes.json in .env
envgo run dev

# Public mode with the dashboard enabled (for debugging only)
envgo --config envgo.routes.json --env .env --dashboard

# HTTPS with a self-signed certificate
envgo --tls --dir . --env .env --allow api.openai.com

# Create a starter project
envgo init
envgo init -name myapp

# Generate deployment configs
envgo deploy -o ./deploy

# Update envgo in place
envgo run update

# Force a hard reload in every dev-server browser tab
envgo cache clear

# Show help (what a bare `envgo` does)
envgo
```

`envgo deploy -o ./deploy` writes three files: `Caddyfile`, `nginx.conf`, and
`Dockerfile`. See [Docker Deployment](/guides/docker-deployment) for how to use
them.

## What `envgo init` creates

Running `envgo init` writes five files into the target directory:

| File | Contents |
|------|----------|
| `.env` | `MY_SECRET=change-me`, `HOST=127.0.0.1`, `PORT=8080`, `# MODE_PUBLIC=false`, `# CONFIG=envgo.routes.json` (mode `0600`, commented by default) |
| `.env.example` | The same placeholder content |
| `index.html` | Minimal page with `<div id="MY_SECRET"></div>` and `/__env.js` |
| `.gitignore` | Ignores `.env`, `*.key`, `*.secret` |
| `README.md` | Generated quick-start notes |

:::caution[`init` overwrites files without asking]
`envgo init` only checks whether the **directory** exists (and only in
`-name` mode). Running it in a directory that already has `index.html`,
`README.md`, `.gitignore`, or `.env` **overwrites those files**. Back up first,
or use `envgo init -name <newdir>`.
:::

Also note that `.env` and `.env.example` are written with *identical* content, so
the generated `.env` holds a placeholder, not a real secret. Edit `.env` before
running.
